# AI Report Summaries (Gemini)

Read PROJECT-BRIEF.md and docs/BUILD-CONVENTIONS.md first.
Step 1: short plan, wait for my confirmation.

## Goal
Each report (screen and weekly email) gets a short written summary at the top, generated by AI from the report's numbers.
Example: "Stock in Yas Network dropped 18% this week. 3 items are below minimum. GRN-PO-2026-0012 had a 5% shortage on batteries. 2 containers have been in the yard over 10 days."

## Rules
- AI is read-only. It never queries the database, never writes, never changes stock.
- The app builds the data; the AI only writes text from the data it is given.
- Send aggregated data only (totals, item codes/names, document numbers, percentages). No user emails, phone numbers, driver details or prices unless the report needs value totals.
- VW and category scope apply: data is built for the viewing user (or the email recipient), so nobody gets a summary of data they cannot see.
- If the AI call fails or is disabled, the report still works; show "Summary unavailable" (never block the report).

## 1. Config and settings
- .env: GEMINI_API_KEY, GEMINI_MODEL, AI_SUMMARIES_ENABLED. config/ai.php reads them (provider = gemini). Never hardcode the key or model.
- Account Configuration > AI tab: enable/disable, daily summary limit per user, language (English / Swahili), monthly token usage.

## 2. Service
- App\Contracts\AiClient interface: summarise(string $system, string $userContent): AiResult (text, input_tokens, output_tokens).
- App\Services\Ai\GeminiClient implements AiClient:
    - Laravel Http POST to the Gemini API generateContent endpoint for GEMINI_MODEL.
    - API key in the x-goog-api-key header (never in the URL or logs).
    - System instruction + user content, temperature 0.2, max output tokens 600, timeout 30s, 1 retry.
    - Read token counts from usageMetadata.
    - Bind AiClient to GeminiClient in a service provider so the provider can be swapped later.
- App\Services\Reports\ReportSummaryService:
    - buildPayload(reportType, filters, user): compact JSON of the report's key figures plus the previous period for comparison.
    - summarise(payload): system instruction says: warehouse analyst; 3-6 short bullet points; plain language; only use numbers present in the data; mention the biggest changes, risks and items needing action; no guesses; no greetings; answer in the selected language.
    - Store in report_summaries: report_type, scope_hash (user VWs + categories + filters), period_start, period_end, language, summary_text, provider, model, input_tokens, output_tokens, created_by, created_at.
    - Reuse a stored summary for the same report_type + scope_hash + period + language (no repeat API call).
    - "Regenerate" forces a new one (counts toward the daily limit).

## 3. Reports covered (build payloads for these)
1. Stock summary: stock by department and category, change vs previous period, low stock, out of stock, stock value.
2. Inbound: POs received, GRNs, short/excess/damaged lines, top discrepancy suppliers, pending verification.
3. Outbound: MRNs dispatched, on-time vs late, top moving items, pending approvals.
4. Expiry and ageing: expired, expiring 0-30 / 31-90 days, slow-moving items (no movement 90+ days).
5. Yard: containers in yard, dwell over warning/critical.
6. Adjustments and counts: adjustments by reason, count variances, top variance bins.
   If a Reports page for these does not exist yet, create one with filters (warehouse, department, date range), these 6 report tabs using x-ui.table, and Excel export.

## 4. UI
- Summary card at the top of each report: bullet points, "AI-generated summary, check figures in the report below" note, generated time, Regenerate button, language switch.
- Generate via a queued job; the page loads instantly and shows a loading state until the summary is ready (Livewire polling or event).
- Same glass card design and brand colours as the rest of the app.

## 5. Weekly email
- Scheduled command every Monday 07:00 (Africa/Dar_es_Salaam): for each department head (departments.head_user_id) and departments.report_email, build the weekly report in that recipient's scope, generate the summary, and email it with the Excel attachment.
- Queued, one job per recipient, idempotent per recipient per week.

## 6. Permissions
- reports.view: warehouse-manager, system-admin, data-analyst, viewer-auditor, department-user (own scope), category users (own categories).
- reports.ai_summary: same roles.
- settings.manage: AI tab.

## 7. Audit and cost
- Log every generation in the activity log (user, report type, tokens, provider, model). Never log the API key or full payload.
- Monthly token usage shown in the AI settings tab.
